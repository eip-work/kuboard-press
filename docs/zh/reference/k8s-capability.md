# 集群能力（K8s Capability）

Kuboard 会根据集群的 Kubernetes 版本与组件能力，自动决定某些功能入口是否可用、表单里有哪些选项，以及内部使用哪个 API 版本。**整个过程自动完成，无需配置，也不需要你关注。**

能力的判定结果不直接展示给用户，而是体现在界面行为上，例如：

- 集群不支持临时容器时，不显示「Pod 调试」入口；
- 集群未安装 Prometheus 时，MCP 中隐藏 `prometheus_*` 工具；
- 端口转发传输协议、终端关闭帧处理等内部实现按版本自动选择。

## 受集群版本影响的界面功能

下表列出由集群能力探测机制（K8s Capability）在界面上可感知的版本差异。若你在界面上看不到表中某项，通常是集群版本低于所需版本：

| 界面功能 | 所需 K8s 版本 |
| --- | --- |
| Service / Ingress 表单的 appProtocol 字段 | ≥ 1.20 |
| 「Pod 调试」入口（临时容器） | ≥ 1.23 |
| NetworkPolicy 表单的 ipBlock except CIDRs 字段 | ≥ 1.25 |
| 命名空间 / 工作负载的 Pod 安全（PSA）能力 | ≥ 1.25 |
| RuntimeClass 表单的调度（scheduling）字段 | ≥ 1.27 |
| PVC / PV 表单的 ReadWriteOncePod 访问模式 | ≥ 1.34 |

其余实现细节（驱逐 / CRD / 流控 / metrics 的 API 版本、端口转发传输协议、内置 Helm 版本等）均按集群版本自动选择，界面表现一致，无需关注。

## 集群升级后何时生效

集群升级后无需手动处理：

- 更新集群信息（导入 / 更新集群）后，**立即**按新版本重新判定并生效；
- 否则最多等待 1 小时（判定结果缓存自动过期后重算）。

::: tip 为什么界面上看不到某项功能？
- 集群版本低于该功能所需版本（见上表）；
- 或能力暂时无法探测（集群临时不可达等）——此时 Kuboard 采取放行策略：功能入口保持可用、MCP 工具保持可见，不会因临时故障误伤操作，稍后会自动恢复。
:::
