# Kuboard v4.x Changelog

Kuboard v4 release notes. If you have already installed Kuboard v4.x (a version number starting with v4, e.g. kuboard v4.0.0.0 / v4.0.0.1 / v4.2.1.0), upgrading to a newer v4.x version only requires changing the image tag.

## v4.3.3.0

Release date: 2026-10-27

- New Features:
  - Global Search:
    - Added a site-wide search overlay that spans resource types, letting you locate K8s objects by cluster and resource type
    - Search now supports selecting multiple clusters and rotates hits across clusters; the resource-type dropdown shows cache status and automatically disables types that cannot be found
    - Scope selection (cluster / resource type) is remembered locally, so nothing has to be re-picked next time
    - Added a guide that points first-time users to Global Search right after login
  - System Settings:
    - Added configuration export / import (snapshot backup and restore) to back up and restore roles, users, authorization rules, system configuration, clusters and more in one go
    - Added configuration backup reminders that nudge administrators to run a backup regularly via the to-do list
    - Added a platform health diagnostics page that automatically classifies common symptoms and offers one-click remediation
    - The health diagnostics page now includes reverse-proxy diagnostics, pinpointing proxy misconfiguration behind "terminal / logs do not work"
  - Workloads & CD:
    - The workload edit page now covers more spec fields, and immutable fields are frozen as read-only
    - Deployment specs gained a pause switch, and pod templates gained scheduling and lifecycle fields
    - DaemonSet specs gained revision history count, minimum ready seconds and maximum surge
    - CronJobs now support a time zone, and Jobs gained completion mode, backoff limit and failure policy
    - HPA v2 gained scaling behaviour and Pods / External custom metrics
  - K8s Object Management:
    - The Service edit form now covers the missing fields, and non-editable scenarios were fixed
    - Custom resource lists now automatically show the columns declared via CRD additionalPrinterColumns
  - Installation & Upgrade:
    - Startup is now explicitly rejected when the database charset is not utf8mb4, with remediation guidance, so Chinese seed data cannot silently fail to load
- Improvements:
  - Cluster Management:
    - The request timeouts for Helm repository updates and Global Search are now configurable, with unchanged defaults
  - Home:
    - Clickable table rows now show a pointer cursor on hover, making interactivity clearer
- Bug Fixes:
  - Installation & Upgrade:
    - Fixed non-idempotent unique-constraint cleanup during upgrades of existing databases, which prevented instances from starting
    - Fixed DDL script defects across all four supported databases: tables missing entirely on MySQL 5.7, and tables missing entirely on PostgreSQL / openGauss
    - DDL failures are no longer downgraded to warning logs, so the platform no longer starts up with missing tables
  - Cluster Management:
    - Fixed pagination SQL syntax errors on PostgreSQL / openGauss that made list requests return 500
    - Fixed the watch heartbeat being overwritten by event writes, which caused cluster sync to stall for no reason
    - Fixed resource-availability hints failing to attribute the real cause
    - Fixed cluster API discovery endpoints being reachable without logging in, which exposed the installed API groups and CRD inventory
  - Audit:
    - Fixed a race condition when multiple replicas create audit tables on a cold start, which prevented instances from starting
  - Login & Authentication:
    - Fixed the OIDC callback address picking up the wrong port behind a reverse proxy, which broke the whole single sign-on flow
  - Users & Permissions:
    - Fixed the password expiry time exceeding the database column range, which made user creation fail (#680)
  - Workloads & CD:
    - Fixed an invalid time-zone name in the timestamp written when restarting a workload, which the apiserver rejected (#679)
    - Fixed saving being rejected by the apiserver after switching the update strategy to "Recreate"
  - K8s Object Management:
    - Fixed a spurious vertical scrollbar appearing in the detail tab content area
  - Terminal:
    - Fixed the log WebSocket missing permission checks, which let unauthorized users read logs they had no access to
    - Fixed file browser path parameters being injectable, which posed a command injection risk
  - System Settings:
    - Fixed system configuration endpoints returning sensitive values such as the JWT private key
    - Fixed broken rendering of the version-update notice and insufficient security attributes on the authentication cookie
  - Build & Integration:
    - Fixed the reverse proxy dropping the port in the HA orchestration, which broke the OIDC single sign-on flow
    - Fixed the OpenAPI documentation URL always returning 404 from outside in the HA orchestration
    - Removed weak trust roots from the JRE trust store bundled in the image, fixing CVE-2026-91403

## v4.3.2.0

Release date: 2026-10-18

- New Features:
  - Terminal:
    - Added a command-history panel that surfaces the write-only command history, making it easy to review and find past commands
  - Node Management:
    - Added a node list view grouped by role with resource statistics (node-pool view)
    - Node detail page now supports editing labels, annotations and taints
    - Node detail page always shows the scheduling-status badge; node list gained a scheduling-status column
    - Node resource metrics now show their data-source basis; list view preference is remembered between sessions
  - Workloads:
    - The pod list on workload detail pages now supports pagination and filtering by name / IP / status
    - DaemonSet status bar gained a "scheduled" metric with unscheduled/mis-scheduled alerts
  - Home:
    - The abnormal-workload list now shows a "reason" column, making the cause of an anomaly obvious at a glance
  - Build & Integration:
    - Added a new HA deployment scenario (PostgreSQL + Redis Sentinel + Keycloak OIDC); deploy.sh gained a deploy-remote subcommand
- Improvements:
  - Cluster Management:
    - List pagination now queries clusters in parallel with proper sort indexes, significantly speeding up large lists
    - Home-page abnormal workloads are now filtered server-side instead of pulling everything to the frontend
  - K8s Object Management:
    - Related-resource graph aggregates sibling nodes and drives fetching from anchors, so extra-large namespaces with thousands of nodes no longer lag
    - Related-resource counts now use declared workload values for more accurate, faster fetching
    - Aligned workload pod-status labels with the status-filter options
  - Monitoring:
    - Extracted a shared metrics panel; the node detail page information architecture now matches the Pod page
    - Metrics charts now label their data source accurately, and the install guidance for history charts was restored
- Bug Fixes:
  - Login & Authentication:
    - Fixed the OIDC landing page returning 404
    - Fixed a login crash when the password expiry time is empty
  - Users & Permissions:
    - Fixed authorization SQL errors on MySQL 8.0 cloud databases, which made permission configuration unusable
  - Cluster Management:
    - Fixed a lock-wait timeout when deleting a cluster because sync tasks were not stopped first
    - Fixed full-sync batch writes failing on openGauss
  - Audit:
    - Fixed the hourly audit table maintenance repeatedly re-creating tables/indexes (1060/1061 errors)
  - Terminal:
    - Fixed the arrow keys / Ctrl+R being intercepted by the terminal, breaking keys in full-screen programs such as vi/less
    - Fixed the terminal "Paste" button doing nothing
  - Workloads:
    - Fixed scale-out / rolling updates being wrongly reported as "release failed"
    - Fixed StatefulSets showing "in progress" even when fully ready
  - K8s Object Management:
    - Fixed completed Job/CronJob pods being flagged as abnormal and stuck on the "abnormal workloads" list
    - Fixed the related-resource panel failing in extra-large namespaces and lagging with thousands of nodes
  - Node Management:
    - Fixed inconsistent memory units and decimal places on the node detail page
  - Visual & Branding:
    - Fixed unreadable text in dialog boxes and form descriptions in dark mode

## v4.3.1.0

Release date: 2026-10-12

- New Features:
  - Monitoring:
    - Added dual-source monitoring on the Pod detail page: metrics-server real-time data alongside metrics-scraper 30-minute charts, with Prometheus-first probing and automatic fallback
    - Added the metrics.server.installed capability probe to surface monitoring capabilities per cluster version
  - Cluster Management:
    - Full sync now writes to the database in batches (multi-row REPLACE for MySQL / ON CONFLICT upsert for PostgreSQL), significantly speeding up large-cluster sync
- Improvements:
  - Cluster Management:
    - The sync status table now scrolls within the list with a fixed header, with a dedicated empty state for filtered results
    - Split the batch write lock down to each (cluster, resource) pair, easing long-tail queuing on large clusters
  - K8s Object Management:
    - Uncached resource lists now load in limit/continue chunks, eliminating lag when loading large lists
    - Optimized cache query performance for Pod lists and the cluster namespace tree
- Bug Fixes:
  - Cluster Management:
    - Fixed the full-sync pagination modeling bug: resources beyond 500 per kind were only ever syncing the first page
    - Fixed full-sync pagination aborting without recovery on transient 410/504/5xx errors
    - Fixed incremental-sync watch falling back to full sync on transient interruptions, causing sync oscillation
  - Audit:
    - Fixed audit index creation failing on database dialects that surface "already exists" with a different exception type
  - Monitoring:
    - Restored the metrics-server and metrics-scraper install entries, and fixed the broken 30-minute chart and real-time data paths on the Pod detail page

## v4.3.0.0

Release date: 2026-10-07

- New Features:
  - Login & Authentication:
    - Added OIDC Single Sign-On (SSO) with multiple IdP support, Silent SSO token refresh and trusted-IdP MFA
    - Redesigned the login page with an architecture-diagram layout, animated background and improved button placement
  - Users & Permissions:
    - Added a business view to role authorization: grant view/create/edit/delete permissions by ticking the left-hand menu tree
    - Role authorization now supports a button-level operation registry and quick role templates
  - Helm:
    - Support installing and upgrading from an offline Chart package upload
    - Added a "Resources" tab on the release detail page, listing the managed K8s objects and their status
  - K8s Object Management:
    - Added a "Related Resources" tab on detail pages, reusing the resource-map capability; the context menu supports "focus on this resource"
    - Rebuilt the namespace overview page as a categorized dashboard
    - Unified list-page optimization across 10+ resource types (Deployments/StatefulSets/DaemonSets/nodes/services/ingresses, etc.): expandable rows, adaptive columns, i18n
    - Container rows now display ports; click a port to open the proxy dialog
  - Cluster Management:
    - Rebuilt the sync status table (sync mode/duration/error highlighting/filtering) and added sync task log querying
    - Support multi-instance high-availability deployment: Redis-coordinated scheduling election, cache invalidation broadcast, cross-instance ID collision avoidance
  - Visual & Branding:
    - Introduced a design-token system and brand theming; detail pages fully card-styled
    - Unified the menu/overview/resource-map icon set onto resourceMap resource icons
- Improvements:
  - Related Resource Map:
    - Canvas now uses a tree layout and bezier edges; the depth slider persists across sessions
  - K8s Object Management:
    - Detail-page experience optimization for workloads (Deployments/StatefulSets/DaemonSets)
    - Reorganized the node detail page information architecture; events fully internationalized
  - Agent Change Approval:
    - Restored list search with server-side filtering by Agent / Plan ID
- Bug Fixes:
  - Security:
    - Fixed the tightened /k8s-api proxy authorization, preventing unauthorized reads of K8s resources
    - Fixed SQL injection in the user/group/role list APIs and several missing button-level authorizations
    - Fixed container file-browser privilege escalation and a missing ownership check on the user profile API
    - Fixed stored XSS via innerHTML rendering and addon documents
    - Fixed JWT weak-key startup blocking (auto-rotating self-heal) and Webhook signature verification
    - Fixed missing rate limiting on login endpoints and SSRF on cluster access URLs
    - Upgraded dependencies to fix high-severity vulnerabilities (CVE-2024-7254, etc.)
  - Cluster Management:
    - Fixed sync task memory exhaustion and scheduler SQL full-table scans
    - Fixed Redis dirty cache data causing frequent sync scheduler errors
    - Fixed PostgreSQL failing to connect on startup
  - Terminal:
    - Fixed the log viewer not auto-reconnecting after a disconnect
  - Agent Change Approval:
    - Fixed irregular resource-name derivation errors and step time-semantics issues
  - K8s Object Management:
    - Fixed unscheduled Pods rendering empty node links and charts not refreshing after switching Pods
    - Fixed the CronJob detail task list stacking and detail-page button wrapping
  - Helm:
    - Fixed the install button 404 navigation and startup failure caused by stale keystore files
  - Build & Integration:
    - Fixed the app version not being injected and new-version check errors
    - Upgraded the runtime base image to GA JDK and improved the container startup script
